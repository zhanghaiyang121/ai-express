## 1. 概述

实现电商后台管理系统的订单全生命周期管理，包括订单列表查询、详情查看、订单创建、状态流转（发货→收货）、订单取消、售后处理（仅退款）、物流信息管理、操作日志追溯。

### 1.1 核心目标

- 支持 **6 种订单状态**的完整流转
- 订单列表支持**多条件筛选 + 分页**，P99 < 200ms
- 所有订单操作产生**操作日志**，可完整追溯
- 与现有 M02-用户管理保持一致的代码架构

### 1.2 一期范围

| 功能 | 范围 |
|------|------|
| 售后类型 | 仅退款（refund） |
| 订单来源 | 不区分来源 |
| 物流对接 | Mock 手动录入，不对接第三方 API |
| 支付对接 | Mock 模拟支付，不对接支付网关 |

### 2.3 订单状态机

#### 状态定义

| 状态值 | 中文名称 | 说明 | 是否终态 |
|--------|---------|------|:---:|
| `pending_payment` | 待付款 | 下单后初始状态 | ❌ |
| `pending_shipment` | 待发货 | 支付完成，等待发货 | ❌ |
| `shipped` | 已发货 | 已出库，运输中 | ❌ |
| `completed` | 已完成 | 确认收货 / 售后完成 | ✅ |
| `canceled` | 已取消 | 超时未付 / 用户取消 | ✅ |
| `after_sale` | 售后中 | 仅退款处理中 | ❌ |

#### 状态流转图

```
     ┌──────────────────┐
     │  PENDING_PAYMENT  │  ← 下单后初始状态
     │     待付款        │
     └───┬──────────┬───┘
 支付成功 │          │ 取消
         ↓          ↓
  ┌────────────┐  ┌──────────┐
  │ PENDING_   │  │ CANCELED │  ← 终态
  │ SHIPMENT   │  │  已取消   │
  │  待发货     │  └──────────┘
  └─────┬──────┘
  发货   │
         ↓
  ┌────────────┐
  │  SHIPPED   │
  │  已发货     │
  └──┬────┬────┘
确认收货│    │ 申请售后（仅退款）
       ↓    ↓
┌──────────┐ ┌───────────┐
│COMPLETED │ │AFTER_SALE │
│  已完成   │ │  售后中    │
└──────────┘ └──┬───┬────┘
  终态          │   │ 拒绝，恢复
  退款完成      ↓   ↓
          COMPLETED  SHIPPED
```

#### 流转规则表

| 当前状态 | 允许操作 | 目标状态 | 条件 |
|----------|---------|---------|------|
| `pending_payment` | 支付成功 | `pending_shipment` | 模拟支付 |
| `pending_payment` | 取消订单 | `canceled` | 需填取消原因 |
| `pending_shipment` | 发货 | `shipped` | 需填物流公司+单号 |
| `pending_shipment` | 申请仅退款 | `after_sale` | 未发货前可退款 |
| `shipped` | 确认收货 | `completed` | - |
| `shipped` | 申请仅退款 | `after_sale` | 已发货后也可退款 |
| `after_sale` | 同意退款 | `completed` | 退款到账 |
| `after_sale` | 拒绝退款 | `shipped` | 恢复到发货后状态 |

#### 后端状态校验伪代码

```js
const ALLOWED_TRANSITIONS = {
  pending_payment:  ['pending_shipment', 'canceled'],
  pending_shipment: ['shipped', 'after_sale'],
  shipped:          ['completed', 'after_sale'],
  after_sale:       ['completed', 'shipped'],
  canceled:         [],
  completed:        [],
};

function validateTransition(currentStatus, targetStatus) {
  const allowed = ALLOWED_TRANSITIONS[currentStatus];
  if (!allowed || !allowed.includes(targetStatus)) {
    throw new Error(`不允许从 ${currentStatus} 转换到 ${targetStatus}`);
  }
  return true;
}
```

## 3. 核心数据结构

### 3.1 订单主表 `Order`

```typescript
interface Order {
  id: number;                    // 订单ID（自增）
  orderNo: string;               // 订单编号 ORD202608090001
  userId: number;                // 用户ID
  userName: string;              // 用户名（冗余展示）
  status: OrderStatus;           // 订单状态
  totalAmount: number;           // 商品总价
  discountAmount: number;        // 优惠金额
  freightAmount: number;         // 运费
  payAmount: number;             // 实付金额
  // = totalAmount - discountAmount + freightAmount
  payMethod: PayMethod;          // 支付方式
  payTime: string | null;        // 支付时间（ISO 8601）
  receiverName: string;          // 收货人
  receiverPhone: string;         // 收货电话
  receiverAddress: string;       // 收货地址
  remark: string;                // 用户备注
  adminRemark: string;           // 管理员备注
  cancelReason: string | null;   // 取消原因
  cancelTime: string | null;     // 取消时间
  createdAt: string;             // 下单时间
  updatedAt: string;             // 最后更新时间
}

type OrderStatus = 
  | 'pending_payment'
  | 'pending_shipment'
  | 'shipped'
  | 'completed'
  | 'canceled'
  | 'after_sale';

type PayMethod = 'wechat' | 'alipay' | 'card';
```

## 5. 关键业务流程

### 5.1 下单流程

```
1. 管理员填写订单表单（用户、商品、收货信息）
2. 前端校验表单数据
3. POST /api/v1/orders
4. 后端创建订单：
   - 生成订单编号 ORD + YYYYMMDD + 三位序号
   - 设置状态 pending_payment
   - 记录创建日志
5. 返回订单详情
6. 前端跳转订单列表/详情
```

### 5.2 发货流程

```
1. 运营人员在订单详情页点击"发货"
2. 弹窗填写：物流公司 + 物流单号
3. PATCH /api/v1/orders/:id/ship
4. 后端校验：
   - 订单状态必须为 pending_shipment
   - 物流公司 + 单号必填
5. 更新状态 → shipped
6. 创建物流记录
7. 记录操作日志
```

### 5.3 售后（仅退款）流程

```
1. 用户在 "待发货" 或 "已发货" 状态申请退款
2. 创建售后单，订单状态 → after_sale
3. 运营人员在售后列表审核
4. PATCH /api/v1/after-sales/:id/audit
   - 通过：售后状态 → completed，订单状态 → completed
   - 拒绝：售后状态 → rejected，订单状态 → shipped（恢复）
5. 全程记录操作日志
```

### 5.4 订单状态流转时序图

```
用户/管理员          系统                  状态变化
    │                 │
    ├─ 创建订单 ──────→│                   pending_payment
    │                 │
    ├─ 支付 ──────────→│                   pending_payment → pending_shipment
    │                 │ (记录支付日志)
    │                 │
    ├─ 发货 ──────────→│                   pending_shipment → shipped
    │                 │ (创建物流记录)
    │                 │
    ┌─ 分支A: 正常完成 ─┐
    │ 确认收货 ───────→│                   shipped → completed
    └────────────────┘
    ┌─ 分支B: 申请售后 ─┐
    │ 申请退款 ───────→│                   shipped → after_sale
    │ 审核通过 ───────→│                   after_sale → completed
    │ 审核拒绝 ───────→│                   after_sale → shipped
    └────────────────┘
    ┌─ 分支C: 支付前取消 ┐
    │ 取消订单 ───────→│                   pending_payment → canceled
    └────────────────┘
```

## 6. 异常处理

| 异常场景 | HTTP 状态码 | 处理方式 | 用户提示 |
|----------|:---:|----------|----------|
| 订单不存在 | 404 | 返回错误信息 | "订单不存在" |
| 状态流转非法 | 400 | 校验 ALLOWED_TRANSITIONS | "当前订单状态不允许此操作" |
| 发货时物流信息缺失 | 400 | 参数校验 | "请填写物流公司和单号" |
| 取消订单未填原因 | 400 | 参数校验 | "请填写取消原因" |
| 售后审核无权限 | 403 | 角色校验 | "无操作权限" |
| 重复发货 | 400 | 状态校验 | "该订单已发货，请勿重复操作" |
| 网络超时 | 500 | 前端超时重试1次 | "网络请求超时，请重试" |
| 服务器内部错误 | 500 | try-catch 兜底 | "系统异常，请稍后再试" |
