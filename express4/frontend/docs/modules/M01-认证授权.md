# M01-认证授权 - 详细设计

> **模块状态**: 🔴 未开始 | **功能总数**: 6 | **优先级**: P0
>
> 本模块负责用户认证、Token 管理和密码重置功能。

---

## 1. 模块概述

### 1.1 技术选型
- **认证方式**: JWT (Access Token + Refresh Token)
- **Token 存储**: Access Token (内存/localStorage) | Refresh Token (httpOnly Cookie 或 数据库)
- **密码加密**: bcrypt (saltRounds=10)
- **Token 有效期**: Access Token 30分钟 | Refresh Token 7天

### 1.2 目录结构 (规划)
```
src/
├── modules/
│   └── auth/
│       ├── auth.controller.ts    # 控制器 - 处理请求/响应
│       ├── auth.service.ts       # 业务逻辑层
│       ├── auth.routes.ts        # 路由定义
│       ├── auth.validation.ts    # 请求参数验证
│       └── auth.types.ts         # 类型定义
├── middleware/
│   ├── auth.middleware.ts        # JWT 验证中间件
│   └── rate-limiter.ts           # 限流中间件
└── utils/
    ├── jwt.ts                    # JWT 工具函数
    └── password.ts               # 密码工具函数
```

## 2. 功能详细设计

### M01-01 用户登录
| 属性 | 内容 |
|------|------|
| **状态** | 🔴 未开始 |
| **端点** | `POST /api/v1/auth/login` |
| **认证** | 无需认证 |
| **限流** | 每 IP 每分钟 5 次 |

#### 请求体
```json
{
  "username": "admin",
  "password": "securePassword123"
}
```

#### 成功响应 (200)
```json
{
  "success": true,
  "code": 200,
  "message": "登录成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "dGhpcyBpcyBhIHJlZnJl...",
    "expiresIn": 1800,
    "user": {
      "id": 1,
      "username": "admin",
      "nickname": "管理员",
      "avatar": "https://cdn.example.com/avatar.png",
      "roles": ["admin"]
    }
  },
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

#### 错误响应
| 场景 | 状态码 | errorType | message |
|------|--------|-----------|---------|
| 用户名不存在 | 401 | UNAUTHORIZED | 用户名或密码错误 |
| 密码错误 | 401 | UNAUTHORIZED | 用户名或密码错误 |
| 账号已禁用 | 403 | FORBIDDEN | 账号已被禁用 |
| 参数缺失 | 400 | VALIDATION_ERROR | 用户名和密码不能为空 |

#### 业务逻辑
1. 验证请求参数 (username, password 必填)
2. 根据 username 查询用户
3. 验证密码 (bcrypt.compare)
4. 检查用户状态 (是否禁用)
5. 生成 Access Token 和 Refresh Token
6. 记录登录日志
7. 返回 Token 和用户信息

### M01-02 Token 刷新
| 属性 | 内容 |
|------|------|
| **状态** | 🔴 未开始 |
| **端点** | `POST /api/v1/auth/refresh` |
| **认证** | Refresh Token |
| **限流** | 每用户每分钟 3 次 |

#### 请求体
```json
{
  "refreshToken": "dGhpcyBpcyBhIHJlZnJl..."
}
```

#### 成功响应 (200)
```json
{
  "success": true,
  "code": 200,
  "message": "Token 刷新成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "bmV3IHJlZnJlc2ggdG9r...",
    "expiresIn": 1800
  },
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

#### 业务逻辑
1. 验证 Refresh Token 有效性
2. 检查 Refresh Token 是否已被撤销
3. 生成新的 Access Token 和 Refresh Token (轮换)
4. 标记旧 Refresh Token 为已使用
5. 返回新 Token


4. 返回成功

### M01-04 忘记密码
| 属性 | 内容 |
|------|------|
| **状态** | 🔴 未开始 |
| **端点** | `POST /api/v1/auth/forgot-password` |
| **认证** | 无需认证 |
| **限流** | 每 IP 每 5 分钟 1 次 |

#### 请求体
```json
{
  "email": "user@example.com"
}
```

#### 成功响应 (200)
```json
{
  "success": true,
  "code": 200,
  "message": "重置邮件已发送",
  "data": null,
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

#### 业务逻辑
1. 验证 email 格式
2. 查询邮箱对应账户 (模糊提示，不暴露是否存在)
3. 生成密码重置 Token (有效期15分钟)
4. 发送重置密码邮件 (含重置链接)
5. 统一返回成功 (防止用户枚举)

### M01-05 重置密码
| 属性 | 内容 |
|------|------|
| **状态** | 🔴 未开始 |
| **端点** | `POST /api/v1/auth/reset-password` |
| **认证** | 重置 Token |

#### 请求体
```json
{
  "token": "reset-token-from-email",
  "newPassword": "NewSecurePass123!"
}
```

#### 成功响应 (200)
```json
{
  "success": true,
  "code": 200,
  "message": "密码重置成功",
  "data": null,
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

#### 业务逻辑
1. 验证重置 Token 有效性和有效期
2. 验证新密码强度 (至少8位，含大小写字母+数字)
3. 加密新密码 (bcrypt)
4. 更新用户密码
5. 标记重置 Token 为已使用
6. 强制用户重新登录 (失效所有 Token)

## 3. 数据模型

### 3.1 User (用户表)
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INT | ✅ | 主键，自增 |
| username | VARCHAR(50) | ✅ | 用户名，唯一 |
| password_hash | VARCHAR(255) | ✅ | bcrypt 哈希 |
| email | VARCHAR(100) | ✅ | 邮箱，唯一 |
| nickname | VARCHAR(50) | ✅ | 昵称 |
| avatar | VARCHAR(500) | ❌ | 头像 URL |
| status | TINYINT | ✅ | 0-禁用 1-正常 |
| last_login_at | DATETIME | ❌ | 最后登录时间 |
| created_at | DATETIME | ✅ | 创建时间 |
| updated_at | DATETIME | ✅ | 更新时间 |

### 3.2 RefreshToken (刷新令牌表)
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INT | ✅ | 主键，自增 |
| user_id | INT | ✅ | 关联用户 |
| token | VARCHAR(500) | ✅ | Token 哈希 |
| expires_at | DATETIME | ✅ | 过期时间 |
| is_revoked | TINYINT | ✅ | 0-有效 1-已撤销 |
| created_at | DATETIME | ✅ | 创建时间 |

### 3.3 LoginLog (登录日志表)
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INT | ✅ | 主键，自增 |
| user_id | INT | ❌ | 用户ID |
| ip_address | VARCHAR(45) | ✅ | IP 地址 |
| user_agent | VARCHAR(500) | ❌ | User-Agent |
| result | VARCHAR(20) | ✅ | success / failed |
| created_at | DATETIME | ✅ | 登录时间 |

## 4. 安全检查

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 密码强度校验 | 🔴 | 最少8位，含大小写字母+数字+特殊字符 |
| 登录限流 | 🔴 | 每 IP 每分钟 5 次 |
| 密码重置限流 | 🔴 | 每邮箱每 5 分钟 1 次 |
| Token 黑名单 | 🔴 | 登出后 Token 即时失效 |
| 登录日志 | 🔴 | 记录所有登录尝试 |
| 敏感数据脱敏 | 🔴 | 不在日志中记录密码 |
