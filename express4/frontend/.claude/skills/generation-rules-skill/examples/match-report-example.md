# 规则匹配报告示例

## 示例 1：Vue 组件生成

```markdown
## 📋 代码生成规则匹配报告

**任务：** 生成用户列表组件
**匹配时间：** 2026-08-09 10:30:00

### 识别的项目配置
| 配置项 | 值 |
|--------|-----|
| 框架 | Vue 3.5.0 |
| 语言 | TypeScript 5.5 |
| 构建工具 | Vite 5.4 |
| 状态管理 | Pinia 2.2 |
| UI 组件库 | Element Plus 2.8 |
| CSS 预处理 | SCSS |

### 应用的规则集

#### 强制规则（12 条）
1. ✅ 使用 `<script setup lang="ts">`
2. ✅ Props 用 `defineProps<T>()` 定义类型
3. ✅ Emits 用 `defineEmits<T>()` 定义类型
4. ✅ 异步操作必须有 try/catch/finally
5. ✅ 样式使用 `<style scoped lang="scss">`
6. ✅ 禁止 any 类型
7. ✅ 禁止 v-html 渲染用户输入
8. ✅ 禁止在 template 中写复杂表达式
9. ✅ 列表渲染必须有唯一 key
10. ✅ 颜色使用 SCSS 变量，不硬编码
11. ✅ 导入顺序：类型 → 第三方 → 内部模块 → 相对路径
12. ✅ 单文件不超过 300 行

#### 推荐规则（6 条）
1. ⚠️ 函数长度 ≤ 50 行
2. ⚠️ 参数 ≤ 3 个（超过用对象）
3. ⚠️ 嵌套 ≤ 3 层
4. ⚠️ 大对象用 shallowRef
5. ⚠️ 大列表考虑虚拟滚动
6. ⚠️ 频繁操作加防抖/节流

#### 可选规则（3 条）
1. ℹ️ 添加 JSDoc 注释
2. ℹ️ 使用 design token
3. ℹ️ 添加组件单元测试

### 特殊要求
- 用户要求使用 Element Plus 的 Table 组件
- 需要支持分页和排序

### 规则确认
- [x] 已识别技术栈
- [x] 已加载强制规则
- [x] 已加载推荐规则
- [x] 准备生成符合规范的代码

**状态：✅ 规则匹配完成，准备生成代码**
```

## 示例 3：API 接口层生成

```markdown
## 📋 代码生成规则匹配报告

**任务：** 生成用户模块 API 接口
**匹配时间：** 2026-08-09 11:30:00

#### API 层规则（10 条）
1. ✅ 通过统一 axios 实例发请求
2. ✅ 使用泛型 ApiResponse<T> 返回值
3. ✅ 接口参数必须有类型定义

5. ✅ 函数名：camelCase（getUserList）

8. ✅ 统一错误提示
9. ✅ 接口按模块组织
10. ✅ 导出函数必须有 JSDoc 注释

### 文件结构
```
api/
├── index.ts          # axios 实例（已存在）
└── modules/
    └── user.ts       # 用户模块接口（新建）

types/
└── api.d.ts          # 类型定义（追加）
