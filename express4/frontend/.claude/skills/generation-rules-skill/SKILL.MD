# 代码生成规则匹配 Skill

## Description
每次生成代码前自动匹配并应用代码生成规则。确保生成的代码符合项目规范、技术栈约束、安全要求和最佳实践。在编码前拦截不合规的代码生成。

---

## 触发时机

**在以下场景自动触发规则匹配：**
- 用户要求生成代码（组件/函数/页面/配置）
- 用户要求重构现有代码
- 用户要求修复 Bug
- 用户要求添加新功能
- 任何涉及代码生成的任务

---

## 规则匹配维度

### 1. 技术栈规则
```
识别当前项目技术栈，应用对应规则：

Vue 项目 → 使用 Vue 3 + Composition API + <script setup>
React 项目 → 使用 React 18 + Hooks + TypeScript
Node 项目 → 使用 ES Modules + TypeScript
Python 项目 → 使用 Python 3.10+ + Type Hints

禁止：
- Vue 项目中使用 Options API
- React 项目中使用 Class 组件
- TypeScript 项目中使用 any 类型
```

### 2. 代码风格规则
```
通用规则：
- 使用 const/let，禁止 var
- 使用 === 而非 ==
- 函数命名：camelCase
- 组件命名：PascalCase
- 常量命名：UPPER_SNAKE_CASE
- 文件命名：kebab-case 或 PascalCase

格式规范：
- 缩进：2 空格
- 行宽：100 字符
- 字符串：单引号（JS/TS）
- 分号：无分号（JS/TS）
- 末尾逗号：ES5 模式
```

### 3. 架构规则
```
分层规则：
- 组件层：只负责 UI 渲染和用户交互
- 逻辑层：组合式函数（composables/hooks）
- 数据层：Store（Pinia/Zustand/Redux）
- API 层：统一的接口请求封装
- 工具层：纯函数，无副作用

禁止：
- 组件中直接调用 API
- Store 中直接操作 DOM
- 工具函数中包含业务逻辑
```

### 4. 安全规则
```
强制规则：
- 用户输入必须校验和转义
- 禁止 v-html 渲染用户输入（XSS 风险）
- 敏感信息禁止硬编码
- API 请求必须通过拦截器统一处理鉴权
- 表单提交必须前端 + 后端双重校验

依赖安全：
- 优先使用成熟稳定的依赖
- 避免引入过大的依赖包
- 检查依赖的安全漏洞
```

### 5. 性能规则
```
强制优化：
- 路由懒加载：() => import(...)
- 图片懒加载：loading="lazy"
- 大列表：虚拟滚动（>100 条）
- 频繁操作：防抖/节流
- 大对象：shallowRef/markRaw（不需要响应式时）

禁止：
- 在模板中写复杂表达式
- 在循环中使用 index 作为 key
- 不必要的响应式数据
- 未清理的定时器/监听器
```

### 6. 可维护性规则
```
强制要求：
- 函数长度：不超过 50 行
- 参数数量：不超过 3 个（超过用对象）
- 嵌套深度：不超过 3 层
- 魔法数字：必须抽取为常量
- 重复代码：超过 3 次必须抽取

注释要求：
- 复杂逻辑必须有注释
- 公共 API 必须有 JSDoc/TSDoc
- TODO/FIXME 必须标注负责人和日期
```

## 规则匹配流程

```
1. 识别任务类型
   ├─ 生成组件 → 应用组件规则
   ├─ 生成函数 → 应用函数规则
   ├─ 生成页面 → 应用页面规则
   ├─ 生成配置 → 应用配置规则
   └─ 修复 Bug → 应用调试规则

2. 识别技术栈
   ├─ 读取 package.json → 确定框架
   ├─ 读取 tsconfig.json → 确定 TS 配置
   └─ 读取 .eslintrc → 确定代码风格

3. 应用规则集
   ├─ 强制规则（必须遵守）
   ├─ 推荐规则（尽量遵守）
   └─ 可选规则（酌情使用）

4. 生成规则报告
   └─ 列出将要应用的规则清单
```

## 规则报告模板

```markdown
## 📋 代码生成规则匹配报告

**任务：** {task_description}
**技术栈：** {tech_stack}
**匹配时间：** {timestamp}

### 识别的项目配置
| 配置项 | 值 |
|--------|-----|
| 框架 | Vue 3 |
| 语言 | TypeScript |
| 构建工具 | Vite |
| 状态管理 | Pinia |
| UI 组件库 | Element Plus |

### 应用的规则集
#### 强制规则（必须遵守）
1. ✅ 使用 `<script setup lang="ts">`
2. ✅ Props 必须有类型定义和默认值
3. ✅ 异步操作必须有 try/catch
4. ✅ 样式必须 scoped
5. ✅ 禁止 any 类型

#### 推荐规则（尽量遵守）
1. ⚠️ 函数长度不超过 50 行
2. ⚠️ 嵌套深度不超过 3 层
3. ⚠️ 使用组合式函数封装逻辑

#### 可选规则（酌情使用）
1. ℹ️ 添加 JSDoc 注释
2. ℹ️ 使用 design token

### 特殊要求
- [列出用户或项目特有的要求]

### 规则确认
- [ ] 已理解并准备应用上述规则
```
