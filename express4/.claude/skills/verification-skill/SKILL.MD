# 任务自动验证 Skill

## Description
每次任务执行完成后自动触发验证流程。检查交付物是否真实存在、是否满足用户原始需求、是否遗漏关键步骤。在任务结束前拦截低质量交付。

---

## 触发时机

**在以下场景自动触发验证：**
- 用户说"完成"/"好了"/"搞定"后
- 生成了文件（代码/文档/配置）后
- 执行了外部命令后（安装/构建/部署）
- 多步骤任务的最后一步完成后

---

## 验证维度

### 1. 产物存在性验证
```
❌ 声称创建了文件 → 但文件不存在
❌ 声称修改了代码 → 但文件未变化
❌ 声称安装了依赖 → 但 node_modules 中没有
```

**验证命令：**
```bash
# 检查文件是否存在
test -f "path/to/file" && echo "✅ 存在" || echo "❌ 不存在"

# 检查文件内容非空
[ -s "path/to/file" ] && echo "✅ 非空" || echo "❌ 空文件"

# 检查目录结构
find path/to/dir -type f | wc -l

# 检查文件大小合理
stat -c %s path/to/file
```

### 2. 需求完整性验证
```
检查清单：
□ 用户的所有要求是否都已覆盖？
□ 是否有遗漏的功能点？
□ 是否有未处理的边界情况？
□ 错误处理是否完善？
□ 是否符合用户指定的技术栈/规范？
```

### 3. 代码质量验证
```bash
# TypeScript 类型检查
npx tsc --noEmit

# ESLint 检查
npx eslint src/ --ext .ts,.vue

# 单元测试
npx vitest run

# 构建检查
npm run build
```

### 4. 功能可用性验证
```
□ 生成的代码能否正常编译？
□ 生成的文档格式是否正确？
□ 生成的配置是否生效？
□ 外部链接/路径是否可访问？
```

### 5. 副作用检查
```
□ 是否引入了不必要的依赖？
□ 是否修改了不该改的文件？
□ 是否有 console.log / debugger 遗留？
□ 是否有未使用的导入？
□ 是否有 any 类型？
```

```markdown
**任务：** {task_description}
**时间：** {timestamp}

### 产物检查
| 交付物 | 状态 | 说明 |
|--------|------|------|
| {file1} | ✅/❌ | {说明} |

### 需求覆盖
- [x] 需求点1
- [x] 需求点2
- [ ] 需求点3（遗漏）

### 质量检查
- [x] 类型检查通过
- [x] 代码规范通过
- [x] 测试通过
- [ ] 构建失败

### 验证结论
- ✅ **通过** — 可以交付
- ⚠️ **部分通过** — 需要修复 {具体问题}
- ❌ **未通过** — 需要重做，原因：{具体原因}
```
